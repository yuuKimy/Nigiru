# わさびパニック — 職人プレイ改善計画

> **位置づけ**: 既存の「流れてくる寿司を取る」プロトタイプを、職人が客の注文どおりに握ってレーンへ流すゲームへ作り替える計画。  
> **前提**: スマホのブラウザで、説明なしに短時間遊べること。800×600・Phaser 3・木目／レーンの世界観は維持する。

関連する現行仕様は [`wasabi-panic-plan.md`](./wasabi-panic-plan.md)（取る側のプロトタイプ）を参照。本ドキュメントが **これから実装する仕様** の正とする。

---

## 1. 体験の核

プレイヤーは客ではなく **職人**。時間経過で席に客が増え、各自がわさびの量を注文する。プレイヤーはそれに合わせて握り、レーンへ流す。回転寿司らしさは、レーンを皿が通り、席の客が自分の注文だけを取っていくことに出す。パニックは、席が埋まって我慢ゲージが同時に減っていく忙しさで出す。

| 旧 | 新 |
| --- | --- |
| 子供／大人を選んで、自分向きの寿司を取る | 常に職人。客が注文する |
| スペースで中央ゾーンの寿司を取る | わさび量ボタンをタップして握り、レーンへ出す |
| レーンは敵（流れてくるもの） | レーンは自分の出荷経路 |
| わさびはあり／なしの2種 | **なし / 普通 / 大盛り** の3種 |

子供と大人の二択は、プレイヤー属性ではなく **客の見た目と注文の偏り** に移す（子供客は「なし」多め、大人客は「大盛り」多め）。タイトル画面は属性選択をやめ、遊び方の一言＋スタートにする。

## 2. 確定して進めるルール（提案）

実装前にここを正とする。違う場合は、この節だけ直してからコードに入る。

### 2.1 画面と操作

- 解像度は当面 **800×600 横** のまま（`Scale.FIT` でスマホにフィット）。片手タップを優先し、下部に大きいボタンを3つ置く。
- 入力の主は **タップ／クリック**。PC では `1` `2` `3` または `←` `↓` `→` を同じ3種に割り当ててよい。
- 1タップ = そのわさび量で握って **即座にレーン左端へ出荷**。握る→載せるの2アクションにはしない（テンポが落ちるため）。

### 2.2 客と席

- レーン沿いに席を並べる。スマホで読める上限として **最大 4 席**（初期案）。
- 開始時は **1 席だけ** 客がいる。時間経過で空席に客が入店し、店が埋まっていく。
- 入店間隔は序盤は長く、経過時間と繁忙波で短くなる。満席のあいだは入れない。
- 各客は独立して、注文 `none` / `normal` / `extra` と **自分の我慢ゲージ** を持つ。
- 子供客は「なし」多め、大人客は「大盛り」多め（見た目の偏り。注文はフキダシで必ず表示する）。
- 我慢ゲージが尽きる（空になる）と **不満退席**。席が空き、スコアが減る。
- 正しい寿司を受け取った客は **満足退席**。席が空き、スコアが増える。どちらの退席でも空席には、間隔をおいて新しい客が入りうる。

### 2.3 レーン上の受け取り

回転寿司に合わせ、寿司は左から右へ流れ、**通った席の客が、自分の注文と一致した皿だけ取る**。

- 皿の中心が客の受け取り幅に入ったとき、注文とわさび量が一致していればその客が取る（左の席から優先）。
- 一致しない皿は素通りして次の席へ進む。
- 誰にも取られず右端まで行った皿は破棄。ペナルティはなし（出し直しできる余白を残す）。
- 同じ注文の客が複数いるときは、**皿が先に到達した席** が取る。

### 2.4 判定

| 結果 | 条件 | 効果 |
| --- | --- | --- |
| 正解 | 皿が、注文の一致する客に受け取られた | スコア加算、コンボ+、その客は満足退席 |
| 素通り | 皿が注文と違う客の前を通過した | なし（客は待ち続ける） |
| 誰も取らない | 皿が右端まで流れた | 皿を破棄。スコア・ライフはそのまま |
| 不満退席 | その客の我慢ゲージが尽きた | **スコア減少**（0未満にしない）、コンボリセット、席が空く。クレーム（ライフ）-1 |

ライフ（クレーム）は現行どおり初期 **3**。退席3回でゲームオーバー→タイトル。スコア減だけでは開始直後の0点から終わりにくいので、閉店条件はクレーム側に残す。

### 2.5 難易度（パニック）

- 序盤: 客は少なく、我慢ゲージに余裕、なし／普通が多め
- 時間経過: 入店が速くなり、席が埋まっていく
- **繁忙波**（10〜15秒）: 入店がさらに速く、新規客のゲージが短い、大盛りが増える。波のあと一息
- コンボが高いほど、新規客のゲージがわずかに短い。下限は、レーン移動中に届く時間が残る長さにする

### 2.6 スコア（初期案、実装後に調整）

- 正解: 100 × コンボ倍率（最大 ×5）
- 我慢ゲージが残っているほどわずかに加点（早出し、最大 +50 程度）
- 不満退席: **-150**（所持スコアから引き、0が下限）
- 値は実装後に触る

## 3. 画面構成

```
Boot → Title（旧 Select を改修） → Game → ゲームオーバーは Game 内 → Title
```

`SelectScene` は残しつつ中身をタイトル＋スタートに替える。Scene 名のリネームは必須ではない。

### 3.1 タイトル

- 既存の木札「わさびパニック」
- 一言: 「注文どおりに握って流せ」
- なし／普通／大盛りの3アイコンでルールを見せる
- スタート（大きな皿ボタン1つでよい）

### 3.2 プレイ画面（概念）

```
┌────────────────────────────────────────────┐
│ SCORE    COMBO    クレーム(ライフ)            │
│  [客]なし ██  [客]普通 ███  [客]大盛り █     │
│ ════════════════════════════════════════    │
│  職人 → 皿 → → 席1 → 席2 → 席3 → 席4 →     │
│ ════════════════════════════════════════    │
│  [なし]        [普通]        [大盛り]        │
└────────────────────────────────────────────┘
```

- 上: HUD。客はレーンの上側に席ごとに並べ、フキダシ＋我慢ゲージを各自付ける
- 中: 既存レーン。寿司は **左（カウンター）から右へ**、席の前を順に通る
- 下: 3ボタン（目安 幅 140以上）

判定ゾーン「ここ!」と箸は外す。席の受け取り位置は、客の下に短い印だけ置く。

## 4. 技術方針

現行の慣習を維持する。`GameScene` に詰め込みすぎたら、注文キューとわさび種別だけ `src/game/orders.ts` のような小さいモジュールに分ける。

| 残す | 捨てる／入れ替える |
| --- | --- |
| Boot、木目、レーン画像、スコア／ライフ／コンボ、ゲームオーバー、SoundFx の unlock | 属性 `child`/`adult` によるターゲット判定 |
| 寿司の `update` で X 加算（物理エンジンなし） | 中央ゾーン＋スペースで取る |
| Gemini タッチのスプライト | 空のトラップ皿を取るミス（役割が消える） |

出荷した寿司は Container で右へ動かす。各席の X 範囲に入ったとき、その席の客の注文と照合する。一致ならその客と皿を消す。客・席の状態は `GameScene` が膨らんだら `src/game/customers.ts` に分ける。

タッチは `pointerdown` を3ボタンに付ける。PC キーは任意で同じハンドラを呼ぶ。

## 5. 素材計画

方針は現行どおり、**Gemini で生成 → マゼンタ背景で切り抜き → `public/assets/`**。既存のマグロ・わさび・皿・レーン・木目はできるだけ再利用する。

### 5.1 既存を使う

| 素材 | 使い方 |
| --- | --- |
| `wood.png` / `lane.png` / `title-plaque.png` | 背景・レーン・タイトル |
| `plate-empty.png` / `plate-red.png` など | 出荷する皿。通常出荷は `plate-empty` または白皿に統一 |
| `maguro.png` または `sake.png` | 握りの本体は1種に固定（判断はわさび量だけにする） |
| `wasabi.png` | 普通・大盛りの山。スケールで量を変える |
| `wasabi-empty.png` | ライフ消費、または「なし」ボタンの空マーク |
| `makisu.png` | ゲームオーバーのリトライ |

握りの種類を増やすと、注文が「ネタ＋わさび」になりスマホでは読めなくなる。**ネタは1種、差分はわさび量だけ** にする。

### 5.2 新規生成するもの

| ID | 内容 | 優先 | メモ |
| --- | --- | --- | --- |
| `order-none` | 注文フキダシ「なし」（わさび無しのマグロ） | 高 | 3種は色と山の大きさで即読めること |
| `order-normal` | フキダシ「普通」（小さなわさび） | 高 | |
| `order-extra` | フキダシ「大盛り」（巨大なわさび顔） | 高 | パニックの顔になるとタイトルと合う |
| `btn-none` / `btn-normal` / `btn-extra` | 下部3ボタン用の大きなアイコン | 高 | タップ領域は画像より広い透明ヒットをコードで確保 |
| `customer-child` | 子供客（バストアップ） | 高 | 最大4席で同時に出す。向きや服違いを2〜3体あると埋まった店に見える |
| `customer-adult` | 大人客 | 高 | |
| `seat` | レーン沿いの空席 | 中 | 空席と着席の差が分かること |
| `counter` | 画面左のカウンター／職人手元 | 低 | レーン左端でも代用可 |

わさび量の寿司本体は、新規3枚を描くより **同じ握り＋わさび画像の display size を 0 / 小 / 大** にする方が、読み取りと実装が安定する。大盛りだけはみ出して「危ない量」に見せる。

### 5.3 生成時の指定（共通）

- 既存UIと同じ太めの茶アウトライン、kawaii、木目の上に置く前提
- 背景は切り抜き用の **純色マゼンタ `#FF00FF`**
- フキダシとボタンは、縮小してもなし／普通／大盛りが区別できること（文字だけに依存しない）
- 客はバストアップ、レーンより手前に置ける透過PNG

### 5.4 後回しにしてよいもの

職人の全身立ち絵、客が食べるアニメ、皿の種類を注文ごとに変える、複数ネタ（たまご／いくら等）。テンポの検証が終わってからで足りる。

## 6. 効果音・音楽

現状は `SoundFx.ts` の短い合成音のみで、BGM はない。新ループは **「正しい皿をポンと出せた」** と **「店が混んできた」** の2つが分かれば十分。

### 6.1 効果音

実装は2段。まず既存の Web Audio 合成でプレースホルダを足し、気持ちよさが足りないものだけファイル化する。

| 事象 | 狙い | 初期（合成） | ファイル化する場合 |
| --- | --- | --- | --- |
| ボタンタップ | 握る・叩く | 低めの短い Perc | 手でシャリを握る「ポン」 |
| 出荷 | 皿がレーンに乗る | 高めのクリック | 陶器の軽い接触 |
| 正解到着 | 気持ちよい解決 | 現行 `ok(combo)` を流用 | 客の「うん／いただきます」は任意 |
| 素通り | なくてもよい | — | 控えめなスクロール音程度 |
| 不満退席 | スコアが減ったと分かる | 現行 `miss` | 椅子を引く・ため息 |
| 入店 | 店が混んできた合図 | 短い鈴 | 席に着く音 |
| 繁忙波開始 | パニックの合図 | 現行 `speedUp` | 拍が細かい太鼓 |
| ゲームオーバー | 閉店 | 現行 `gameOver` | のれんを下ろす程度でよい |

スマホは無音スタート規制があるので、**スタートタップで `SoundFx.unlock()`** する現行方針は維持する。

### 6.2 BGM

| 状態 | 内容 |
| --- | --- |
| タイトル | 短いループ、または無音＋SEのみ（実装コスト低） |
| 通常プレイ | 120 BPM 前後の軽い和風ポップ／木魚＋低シンセ程度。メロディは控え、レーンのテンポを邪魔しない |
| 繁忙波 | 同じ曲のドラムを足すか、ピッチ／BPM を約 1.15 倍。別曲に差し替えると境界が分かりやすいが、ループ2本で足りる |
| ゲームオーバー | BGM 停止、SE のみ |

**調達**: 市販の回転寿司・アニメ音源は使わない。候補は (1) 短いオリジナルループを外部の音楽生成で作り `public/assets/audio/` に ogg/m4a で置く (2) プロトタイプ中は BGM なし＋SE のみ。ライセンスが自分たちで説明できるものだけを README に書く。

Phaser の `this.sound.add` でループ再生。ファイルは数 100 KB 級に圧縮し、初回は Boot でプリロードするか、タイトルのスタート後に読み込んで待ちを避ける。

### 6.3 音の受け入れ目安

- 3ボタンを連打しても割れない（同時発音を2〜3に制限）
- 繁忙波に入ったことが、画面演出なしでも音で分かる
- ミュートしてもプレイ可能（音は補助）

## 7. 実装フェーズ

| フェーズ | 内容 | 完了の目安 |
| --- | --- | --- |
| A. 操作の置換 | 取る処理を削除。下部3ボタンで寿司を左端に出し、右へ流す | ボタンで3種の見た目がレーンを流れる |
| B. 客と席 | 最大4席、時間で入店、席ごとゲージ、一致した皿だけ受け取り、ゲージ切れで退席＋スコア減 | 客が増減し、退席で点が減り、3クレームで終了する |
| C. タイトル | Select をスタート画面化。属性 data をやめる | 起動→スタート→プレイ→リトライ |
| D. 素材 | フキダシ・ボタン・客を Gemini 生成して差し替え | 3種が瞬時に区別できる |
| E. パニック | 繁忙波とコンボ連動のゲージ短縮 | 波の入りと終わりが分かる |
| F. 音 | SE 追加、可能なら BGM ループ | スタートタップで音が出る |
| G. スマホ調整 | ボタンサイズ、誤タップ、横持ち FIT | 実機ブラウザで1分遊べる |

A→B までが「ゲームとしての楽しさ」の検証最小単位。D より先に B を遊べる状態にする（仮UIは丸と文字でよい）。

## 8. 受け入れ条件

1. タイトルからスタートし、職人として3種のわさび量をタップ出荷できる
2. 時間とともに客が増え、最大席数まで埋まる。各客の注文と我慢ゲージが見える
3. 注文と一致した皿がその客の席で受け取られると加点される。不一致の皿は素通りする
4. 我慢ゲージが尽きると客は退席し、スコアが減る。クレームが尽きるとゲームオーバー→タイトル
5. 下部ボタンだけで（キーボードなしで）最後まで遊べる
6. 繁忙波がある、または同等の「急に忙しくなる」区間がある
7. 効果音がスタート後に鳴る。BGM はなくてもよいが、入れるならループと繁忙で差がある

## 9. スコープ外（この改善ではやらない）

- 縦画面専用レイアウトへの全面変更（必要なら別計画）
- ネタの多種類化、レシピの組み合わせ
- オンラインランキング、アカウント
- 物理演算、レーンの円形化

## 10. モデル・進め方のメモ

この文書は仕様の固定用。実装に入るときは、フェーズ A から小さく Scene を切る通常のコーディングで足りる。

設計の分岐（2アクション握り、縦画面など）をさらに増やして比較したい場合は、Cursor の **Plan モード** でこのファイルを対象にレビューすると、実装と議論が混ざりにくい。文章の推敲やトレードオフの深掘りだけを厚くしたいときは、より長考向けのモデルに切り替えてもよい。ルールとフェーズがこの文書どおりなら、実装モデルはそのままで進めてよい。
