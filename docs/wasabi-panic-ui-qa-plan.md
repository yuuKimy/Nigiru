# わさびパニック — 画面UI見やすさ QA 計画

機能とルールの正は [`wasabi-panic-test-plan.md`](./wasabi-panic-test-plan.md)。  
本計画は **見た目だけ** を対象にする。プレイ数値（速度・我慢・得点）は変えない。

合格の軸は「説明なしに、注文と3ボタンが一目で分かるか」。  
WCAG は目安であり、カジュアルゲームで AA を全部満たすことは求めない。好みは欠陥にしない。

実施は **`npm run preview`**。`npm run dev` は最終確認に使わない。

---

## 方針

見る距離は「腕を伸ばしたスマホ（横向き）」と「ノートPCの通常距離」の2つ。

各画面で次を見る。

- **階層** — 最初に目が行くのは操作対象か（タイトルならスタート、プレイなら3ボタンと客の注文）
- **コントラスト** — 茶文字が木目に沈まないか。赤皿上のクリーム文字が読めるか
- **サイズ** — FIT 縮小後も、注文・ボタン・スコアが読めるか。ゲーム内 16px 以上を「必ず読む文字」の目安にする
- **色の役割** — なし／普通／大盛りが、文字なしでも山の大きさで分かるか。我慢ゲージの緑→黄→赤が焦りとして読めるか
- **重なり** — 職人・スコア皿・先頭客・フキダシ・繁忙表示が食い合わないか
- **状態差** — 空席と着席、コンボ0とコンボ中、ライフ有無、ゲームオーバー前後

対象:

- タイトル … `src/game/scenes/SelectScene.ts`
- プレイ／ゲームオーバー … `src/game/scenes/GameScene.ts`
- フォント … `src/game/theme.ts`（Zen Maru Gothic）

画面は 800×600 の横長が正。スマホも **横向き** で見る。縦向きは `Scale.FIT` でさらに小さく中央に乗るだけで、この計画の合格対象ではない（職人プレイ計画でも縦専用レイアウトはスコープ外）。

横向きの iPhone クラス（論理解像度の短辺が約 390）では、高さ 600 が先に当たるので縮小率は約 0.65。ゲーム内 11px は実表示約 7px 相当になる。ここが文字サイズの本命の弱点。

## 改善の順番（P0 確定後）

主戦場は Scene の `fontSize`・色・配置・アルファ。新フォントや全面テーマ変更はしない。

1. **必ず読む文字を上げる** — フキダシラベル、空席、ボタン、スコア本体。ゲーム内 16〜18px を下限の候補にする
2. **沈む色を切る** — 空席の `#8d6e4c` を `#5d3318` にするか、薄い台を敷く。必要ならごく薄いストローク
3. **HUD の詰まり** — コンボをスコア皿の外へ出すか、SCORE ラベルをやめて数字＋コンボだけにする（見た目のみ）
4. **繁忙とゲームオーバー** — 繁忙は位置か大きさか色を一段強く。ゲームオーバーの暗幕を濃くする
5. **撮り直し** — `scripts/capture-screenshots.mjs` で `docs/images/play.png` / `select.png` を更新

やらないこと: 新フォント導入、全面テーマ変更、プレイ数値の変更、WCAG 自動ツールの常設。

## 実施の順番

1. preview で PC Chrome のタイトル → プレイ → ゲームオーバーを上のチェックで採点する
2. スマホ実機で同じ項目を採点する（縮小が本命）
3. P0 をコードで直す
4. P0 を再確認し、見た目が変わったら README スクショを撮る
5. 余裕があれば P1
