# わさびパニック — ネタ追加改修方針（第2ネタ: たまご）

> **位置づけ**: [`wasabi-panic-chef-plan.md`](./wasabi-panic-chef-plan.md) §5・§9 の「ネタ1種固定」を、**テンポ検証後の最小追加**として更新する方針書。  
> 本書が **たまご追加** の設計正。実装前にここを合意してからコードに入る。

ゲーム性検証（[`wasabi-panic-fun-test-plan.md`](./wasabi-panic-fun-test-plan.md)）では、ネタ多種類化は **V 軸（任意）**。テンポを崩さない範囲で 1 種だけ足す。

---

## 1. 目的

- 画面上の **見た目のバリエーション** を増やし、単調さを減らす
- プレイヤーの **操作次元は 1 つだけ** 増やす（3 ボタン → 4 ボタン）。「ネタ × わさび」の全組み合わせ（6 択以上）にはしない
- 判定の主軸は引き続き **「注文どおりに握って流す」**。読み取りはスマホ横向き FIT で可能な情報量に留める

---

## 2. 基本方針 — 「たまごはわさび無し固定」

### 2.1 追加するネタ

| ネタ | キー | わさび | 理由 |
| --- | --- | --- | --- |
| マグロ | `maguro` | なし / 普通 / 大盛り | 現行どおり |
| **たまご** | `tamago` | **常になし（固定）** | 見た目で即区別。わさび量の判断軸を増やさない |

たまごにわさびを載せない（または載せても注文に出さない）ことで、

- 客の注文: **マグロ＋わさび量** または **たまご（わさび無し）**
- プレイヤー操作: **既存 3 ボタン（マグロ用）＋ たまご 1 ボタン**

となり、選択肢は **4 択**（= 素材の選択肢 +1）に収まる。

### 2.2 やらないこと（スコープ外）

- たまごの普通／大盛り
- マグロ・たまご以外の第 3 ネタ（いくら・エビ等）
- 注文を「ネタ × わさび」の 6 パターン全部に広げる
- 下部ボタンを 2 段（ネタ選択 → わさび選択）にする 2 アクション化
- ネタごとに皿スプライトを変える（`plate-empty` 統一のまま）

---

## 3. ルール（確定案）

### 3.1 注文

各客は次のどちらかを持つ。

```
{ neta: "maguro", wasabi: "none" | "normal" | "extra" }
{ neta: "tamago", wasabi: "none" }   // wasabi は常に none。型上は none 固定
```

- フキダシ: **ネタの見た目（マグロ or たまご）＋ わさびラベル**
  - たまご注文: たまご画像 ＋ **「たまご」** のみ（**わさび山は出さない**）
  - マグロ注文: 現行どおりマグロ ＋ なし／普通／大盛り
- 子供／大人・繁忙による **わさび量の偏り** はマグロ注文にのみ適用。たまご注文の比率は別テーブル（§3.3）

### 3.2 出荷（プレイヤー操作）

| 操作 | 出荷内容 |
| --- | --- |
| 下段「なし」 | マグロ・わさびなし |
| 下段「普通」 | マグロ・普通 |
| 下段「大盛り」 | マグロ・大盛り |
| **下段「たまご」（新規）** | **たまご・わさびなし** |

- 1 タップ = 即レーン出荷（現行どおり）
- 出荷クールダウン・レーン上限は **ネタ共通**（数値変更は別タスク）

### 3.3 判定

| 結果 | 条件 |
| --- | --- |
| 正解 | 皿の **ネタ** と **わさび量** が、客の注文と両方一致 |
| 素通り | ネタまたはわさびのどちらか不一致 |
| 破棄・退席 | 現行どおり |

例:

- 注文がたまご → たまごボタンのみ正解。マグロ＋なしを流しても **素通り**（ネタ不一致）
- 注文がマグロ普通 → 普通ボタンのみ正解。たまごボタンは **素通り**

### 3.4 注文の出現比率

既存の `pickOrder` を拡張するイメージ。**開始値**は下表（fun-test 後に調整可）。

| 条件 | マグロ（従来の wasabi 抽選） | たまご |
| --- | --- | --- |
| 全条件（開始） | 75% | **25%** |

繁忙時だけたまごを増やす等は、開始後の調整候補とする。

## 4. UI / UX

### 4.1 プレイ画面

```
┌────────────────────────────────────────────┐
│  [客] たまご   [客] 普通   [客] 大盛り  …   │
│ ════════════════════════════════════════    │
│  職人 → 皿 → → 席 → …                      │
│ ════════════════════════════════════════    │
│ [なし]  [普通]  [大盛り]  [たまご]           │  ← 4 ボタン
└────────────────────────────────────────────┘
```

- **4 ボタン配置**: 下段を **横 4 等分**（`width * (i + 0.5) / 4`, i = 0…3）。`800×600` でタップ 44px 相当を確保（ui-qa-plan 準拠）
- たまごボタンのプレビュー: `tamago.png` のみ（わさび山なし）。ラベルは **「たまご」**
- 既存 3 ボタンは **マグロプレビューのまま**（ラベルはなし／普通／大盛り）

### 4.2 タイトル画面

- 見本は現行 3 種（わさび量）を維持
- たまごは **小さな 4 点目** として 1 つ添える、またはサブコピー下に「たまごも」の一行＋アイコン 1 つ  
  → 初見で 4 ボタンに驚かない程度の予告（詳細はプレイで学ぶ）

### 4.3 読み取りの原則

1. **ネタは形と色**（赤身 vs 黄たまご）で瞬時に区別
2. **わさびは山の有無・大きさ**（マグロ注文のみ）
3. **文字は補助**（16px 以上。ui-qa-plan）

## 5. 技術方針

### 5.1 データモデル

```typescript
type NetaKind = "maguro" | "tamago";

type Order = {
  neta: NetaKind;
  wasabi: WasabiAmount; // tamago のときは "none" 固定
};

type Shipment = Order; // プレイヤーが出荷する内容
```

- `orders.ts`: `pickOrder` → `pickCustomerOrder()` に拡張（neta + wasabi）
- `rules.ts`: `resolvePlateAtSeats` の一致条件を `plate.neta === order.neta && plate.wasabi === order.wasabi` に
- `Plate` 型に `neta: NetaKind` を追加

### 5.2 触るファイル（想定）

| ファイル | 変更 |
| --- | --- |
| `src/game/orders.ts` | 注文抽選（neta + wasabi） |
| `src/game/rules.ts` | 皿と席の一致判定 |
| `src/game/scenes/GameScene.ts` | 皿ビジュアル、4 ボタン、フキダシ |
| `src/game/scenes/SelectScene.ts` | タイトル見本（任意） |
| `src/game/scenes/BootScene.ts` | `tamago` は **読み込み済み** — 変更最小 |
| `src/game/orders.test.ts` / `rules.test.ts` | たまご注文・不一致ケース |

### 5.3 キーボード（PC）

**現行（3 ボタン）** — `GameScene.pollKeys` で割り当て済み:

| 操作 | 数字キー | 矢印キー |
| --- | --- | --- |
| なし（マグロ） | `1` | `←` |
| 普通（マグロ） | `2` | `↓` |
| 大盛り（マグロ） | `3` | `→` |
| たまご | `4` | — |

タップ／クリックが主入力。キーは補助（[`wasabi-panic-chef-plan.md`](./wasabi-panic-chef-plan.md) §2 どおり）。

**たまご追加時**: `4` でたまご出荷（§10 確定）。

### 5.4 アセット

| `tamago.png` | `public/assets/sushi/` に **既存** |
